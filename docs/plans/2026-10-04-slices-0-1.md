# Postern Slices 0–1 (Foundation + Fake-TLS Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working vertical slice: an admin creates a node and a fake-TLS proxy in the Postern panel, the node (agent + edge + telemt in Docker) serves it, links are byte-compatible with the reference formulas of spec §4, and an L1 fake-TLS probe passes through the edge.

**Architecture:** Go monorepo. `postern-node` binary runs as `agent` (control plane, Docker API, desired-state reconcile, mTLS gRPC for the panel) and `edge` (data plane: SNI router, PROXY v2 to engines, stranger handling, limits, counters, SOCKS egress). Engines are official telemt binaries run in stock `alpine` containers on host network, bound to `127.0.0.1`. `postern-panel` is Go + SQLite + embedded React SPA, talking ConnectRPC to the browser and gRPC-over-mTLS to nodes.

**Tech Stack:** Go 1.27, connect-go + protobuf (buf), modernc.org/sqlite, golang.org/x/crypto, React 19 + TypeScript + Vite + Mantine + TanStack Query + i18next + @connectrpc/connect-web, Docker Engine API (raw HTTP over unix socket).

**Spec:** `docs/design/2026-10-04-postern-design.md` (Russian). Sections referenced as §N.

## Global Constraints

- Module path: `github.com/urbnywrt/postern`; Go `1.27`; all binaries built with `CGO_ENABLED=0`, targets `linux/amd64` and `linux/arm64`.
- Go toolchain lives in WSL Ubuntu, not on Windows. From Git Bash run Go/Docker commands through `bash scripts/wsl '<command>'` (created in Task 1); never put double quotes inside `<command>` — write a script file under `scripts/` or the SDD workspace for anything complex.
- Git commits are made from Windows Git Bash (identity already configured). Conventional commits in English. **No `Co-Authored-By` or any other trailer.** Never `--no-verify`.
- Repository hygiene: only documentation addresses in code/tests/docs/commit messages: `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `2001:db8::/32`, domains `example.com`, `*.example`, `*.test`. Telegram DC addresses (`149.154.175.50`, `149.154.167.51`, `149.154.175.100`, `149.154.167.91`, `91.108.56.130`) and loopback are allowed. No real hostnames, tokens or personal data.
- Logging: `log/slog`. Never log proxy secrets, private keys, tokens, passwords, TOTP secrets.
- Tests: standard `testing` package, table-driven; `github.com/google/go-cmp/cmp` allowed for diffs. Integration tests needing Docker or network use build tag `integration`; e2e uses tag `e2e`.
- Do not run `go mod tidy` on the whole module from a lane worktree; add dependencies with `go get <module>@<version>` only when the task needs them.
- Runner image for every node container: `alpine:3.22@sha256:5291449c3df73caf6ed85e649dec1b9e818b39a5d8c871e97afc13e9cd5e8fa8`.
- telemt default version `3.5.13`. Artifacts (tar.gz containing the `telemt` binary):
  - `telemt-x86_64-linux-musl.tar.gz` sha256 `7124a854310d4c91a502aeebfd29f7fc6ddef1dcd44eb0cb72e9f9c176582b43`
  - `telemt-aarch64-linux-musl.tar.gz` sha256 `f7b5181f1160e9ec73eb28705040bf159782055ec71f54a20214e2c9a6d997cd`
  - URL pattern `https://github.com/telemt/telemt/releases/download/<version>/<file>` (tag has no `v`).
- Node host layout root `/opt/postern` (`bin/`, `pki/`, `data/state`, `data/edge`, `data/run`, `data/artifacts`, `data/instances`, `data/certs`, `data/stats.db`). Overridable with env `POSTERN_HOME` (tests use temp dirs).
- Container labels: `postern.managed=true`, `postern.role` ∈ {`agent`,`edge`,`engine`,`egress`}, `postern.id`, `postern.generation`. Names: `postern-agent`, `postern-edge-g<N>`, `postern-eng-<lowercase proxy id>-g<N>`, `postern-egr-<lowercase egress id>-g<N>`. All `network_mode: host`.
- Loopback port ranges: engines 20000–24999, engine API 25000–29999, edge SOCKS 30000–34999, egress SOCKS 35000–39999, service (test listeners, mgmt, http-upstream) 40000–40999.
- Edge timeouts: ClientHello read 10 s, max ClientHello bytes 65536, relay idle 15 min, upstream dial 4 s, device idle window 120 s.
- Links must be byte-identical to the reference formulas in spec §4 (JS `encodeURIComponent` semantics, lowercase hex of UTF-8 domain, secret/domain stored as-is).
- Panel data dir `/data` (env `POSTERN_DATA`), key dir `/keys` (env `POSTERN_KEYS`, file `master.key`). Panel listens on `:8080` by default (env `POSTERN_LISTEN`).
